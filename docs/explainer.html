An AI build crew that asks you twice and proves the rest.

Two gates. Evidence for everything else.

lean-sdd turns Claude into a project lead for software work. You sign off on the plan at the start and the result at the end. In between, Claude splits the work, hands pieces to specialist AI helpers, has every piece checked, and shows proof that each promise was kept.

lean-sdd is a spec-driven development workflow for Claude Code: spec → plan → parallel build in worktrees → per-task review → multi-seat review panel → per-criterion spec converge → merge. You approve the spec and the merge; everything between is decided on evidence, with ambiguity batched into one question round.

Step zero

First question: is this worth a process at all?

Most process tools treat a typo fix like a product launch. lean-sdd sizes the job first and gets out of the way for small work.

Built-in brakes

It can't loop forever, and the lead never drowns in detail

One task's life

Each piece of work gets built and checked. If the checker finds problems, it gets at most two retries. After that it is marked stuck and the rest of the project keeps moving.

Max 2 fix rounds per task. Re-reviews use the cheap reviewer on the fix diff only. Still failing → blocked in the ledger, independent tasks continue, reported at milestone end.

The lead reads reports, not code

The main Claude session acts like a manager with a strict inbox rule: helpers send back a 10-line summary, never the whole pile of changes. That keeps the manager sharp for long projects.

The coordinator never reads full diffs during build or review. Agents read a review package from review-pkg.sh; the coordinator reads 10–15-line reports. Fixes of 10 lines or fewer it may make itself, batched for one cheap review. The plan file's ledger is the source of truth for pause and resume.

The crew

Ten specialists, each on the cheapest model that can do the job

Simple chores go to the fastest, cheapest AI. Judgment calls go to stronger ones. The most expensive model is saved for security review.

Model and effort live in each agent's frontmatter. Dispatched as lean-sdd:<name>. panel-correctness escalates to Opus only when a trust boundary exists.

Who decides what

Autonomy with a clear line

Each gate needs an explicit yes. Picking an option in a question is not approval.

You approve

Two moments

  • The spec: what will be built and how success is measured
  • The merge: shipping the result

Claude decides

On evidence

  • The plan and task split
  • Which agent builds each task
  • Fixes for problems two reviewers both raise
  • Merge order of parallel work

Claude asks you

Batched, best option first

  • Dismissing a review finding
  • Skipping a review step
  • Going past a retry cap
  • Starting a task before its dependency
  • User-facing wording

For developers

lean-sdd is a Claude Code plugin that runs spec-driven development end to end. Small changes skip it. For features it writes a spec with testable acceptance criteria, plans interfaces and tests, builds tasks in parallel worktrees, reviews each task with capped fix rounds, runs a multi-lens review panel, then verifies every criterion before merge. We only approve the spec and the merge.

For product and business

It turns Claude into a project lead with a crew. We sign off twice: on what gets built, and on shipping it. In between, AI helpers build and check the work, and before we ship we get a line-by-line report of which promises were proven. Small fixes skip all of that, so we only pay for process when the job is big.

For managers

It keeps AI-driven work predictable: two fixed approval points, a hard cap on rework loops, cheaper models for simple tasks, and a pause before usage limits run out. Each project ends with a short retro that turns mistakes into automatic checks, so the process gets tighter with use.
